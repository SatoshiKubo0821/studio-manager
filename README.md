# Studio Manager by Metaland Tokyo

複数スタジオ対応の予約・売上管理ツール(Metaland Tokyo / Studio VirtuaReal)。

本番URL: https://studio.metalandtokyo.xyz

## 機能

- ダッシュボード(月別の売上・入金状況)
- 予約管理
- 銀行明細ペーストによる入金消込
- 顧客名簿
- クーポン管理
- メール文章作成(受信メール本文を貼り付け → テンプレートから確定メール文章を作成。送信は各自のメールソフトから)
  - 変数は日本語(`{{お客様名}}` `{{オプション}}` `{{人数追加}}` など)でも英語キー(`{{customerName}}` など)でも書けます: お客様名・スタジオ名・予約日・開始/終了時刻・プラン名・合計金額・連絡先・オプション(`{{options}}`)・利用人数(`{{people}}`)・人数追加(`{{extraPeople}}`。合計金額はプラン＋オプション＋人数追加。「×N名」の記載、または利用人数とプランの基本人数の差から計算し、スタジオの「人数追加」オプションの単価で金額を表示)
- スタジオ別の料金設定(プラン・オプション・延長料金)
- スタジオ管理
- メンバー管理(招待制。アドミン/マネージャー/スタッフの3ロール)

## 構成

- `index.html` — アプリ本体(単一ページ。ビルド不要)
- Firebase プロジェクト: `studiomanager-5eb1d`
  - Hosting: `studiomanager-5eb1d.web.app`(独自ドメイン `studio.metalandtokyo.xyz` を CNAME で割り当て)
  - Authentication: メールアドレス+パスワード
  - Firestore: データ保存。ロールごとの権限は `firestore.rules` で制御
  - 同じプロジェクトを写真事業向けの別アプリ Photo Manager(`../photo-manager`)も使います。`photoBookings` / `photoConfig` のルールもこのリポジトリの `firestore.rules` で管理しています

## 予約表の取り込み(更新ボタン・毎朝の自動取り込み)

- ダッシュボードの「↻ 予約表から更新」(マネージャー以上): 全スタジオの予約表を読み、新規の予約だけを取り込みます(支払状況は未収)。既存予約と重複の可能性がある行は取り込まず「要確認」として件数を表示します
- 利用人数は確定メールの「ご利用人数」欄(または「N名様でのご利用」)から読み取り、ダッシュボードに平均利用人数を表示します。「更新」時に読み直して直します(予約画面で手入力した人数は上書きしません)
- 撮影内容(作品・キャラ)と利用目的は確定メールの「撮影内容」「作品名・キャラクター名」「撮影予定の作品名・キャラ名」「利用目的」欄から読み取り、ダッシュボードの「撮影内容一覧」に表示します。取り込み済みで空欄の予約は「更新」時に補完します
- 毎朝9:00(日本時間)に GitHub Actions(`.github/workflows/sync-sheets.yml`)が同じ処理を実行します。スクリプトは `scripts/sync-sheets.mjs` で、読み取り処理は `index.html` から読み込むためアプリと結果が一致します。結果はダッシュボードに「自動取り込み: 日時 新規N件」と表示
- 初期設定:
  1. Google Cloud(`studiomanager-5eb1d`)でサービスアカウントを作成し、ロール「Cloud Datastore ユーザー」を付与、JSONキーを発行
  2. GitHub リポジトリの Settings → Secrets and variables → Actions に `GCP_SA_KEY` としてJSONキーの中身を登録
  3. 各スタジオの予約表を、サービスアカウントのメールアドレスに「閲覧者」で共有
  4. Actions タブの「Sync booking sheets」→「Run workflow」で動作確認(`dry_run` で書き込みなしの確認も可)
- `GCP_SA_KEY` が未設定の間は何もせず終了します

## 顧客管理(CRM)

サイドバーの「顧客管理」。予約データから顧客を自動で名寄せし(名前の空白・「様」の有無を同一視)、店舗をまたいだ利用もまとめて扱います。

- 指標: 顧客数・リピート率・リピーター売上比率・平均LTV・平均利用間隔・休眠顧客数・今月の新規、月別の新規/リピーター予約
- 一覧: 検索、セグメント(新規/リピーター/休眠/VIP=累計売上上位10%/複数店舗/要注意/タグあり)、並び替え、CSV出力(Excel対応)
- 顧客カルテ: 予約履歴、連絡先・SNS・タグ・メモ・要注意フラグの保存、別表記の同一人物の統合(編集・統合はマネージャー以上。スタッフは閲覧のみ)
- 要注意顧客: 予約一覧・入金消込に⚠、予約入力時と取り込みプレビューで警告
- データは Firestore の `customers` コレクション(ドキュメントID は正規化した名前)。名前不明・予約サイト経由の予約は顧客集計から除外
- 画面上の顧客名は姓のみ表示し、名は「＊＊＊＊」でマスキング(例: 安栖 ＊＊＊＊。空白がない名前は先頭2文字)。編集欄・メール文章・CSV出力は氏名をそのまま使います

## SNS分析(X)

サイドバーの「SNS分析」で、店舗ごとのXの月次数値を記録・比較できます(Xアカウントはスタジオの「編集」で登録)。

- 入力項目: フォロワー数(月末)・投稿数・インプレッション・エンゲージメント・プロフィールアクセス・リンククリック・メモ。Xアナリティクスの数値を月ごとに手入力します(マネージャー以上)
- 「全スタジオ」選択時は店舗別の一覧、店舗選択時はKPI(前月比、1投稿あたりインプレッション、エンゲージメント率)と直近12か月の推移(同月の予約件数・売上と並べて表示)
- データは Firestore の `snsStats` コレクション(ドキュメントID: `{studioId}_x_{YYYY-MM}`)

## 公式サイトから料金を読み込む

スタジオの「編集」で公式サイトのURLを登録すると、スタジオ管理の「サイトから料金を読み込む」で、サイトの料金・オプション・アクセスページ(WordPress の REST API)から金額の記載を拾い、プラン・オプション・延長料金・所在地に反映できます。

- 税別表記は税込(×1.1)に換算して表示します。反映前に種類・名前・金額を確認・修正できます
- 同じ名前のプラン・オプションは金額を更新し、ないものは追加します。既存のプランは削除しません(過去の予約との紐づけを保つため)
- 人数ごとの単価(「2名ご利用時 6,000円/名」など)や追加料金の行は、初期状態では「使わない」になります

## Google連携(スタジオごと)

スタジオ管理の「編集」で、予約スプレッドシートのURLとGoogleカレンダーのカレンダーIDを登録できます。登録したスタジオでは「取り込み」から予約をアプリに読み込めます。

- スプレッドシート: 列の対応づけ(日付・時間・お客様名など)はスタジオごとに保存され、次回から自動で使われます
- カレンダー: 時間指定の予定を、タイトル=お客様名・説明=備考として取り込みます
- 同じ行や予定を二重に取り込まないよう、取り込み元を `importKey` で記録しています。同じスタジオ・同じ日時に既存の予約がある行は、初期状態では選択されません
- 取り込んだ予約をアプリで削除すると、次回の取り込みでは再び「新規」として表示されます
- シート側で名前・日付・時刻を直した行は別の予約として扱い、既存の予約は上書きしません(同じ日の同名・同時刻の予約があれば「既存予約と重複?」と表示)
- 支払状況の初期値は「未収」です(支払状況の列がある場合はその値、取り込み画面で切り替え可)
- 読み込めるのは Googleスプレッドシートと、Drive 上の Excel(.xlsx)です
  - 1行1予約の表: 列の対応づけを指定して取り込み
  - カレンダー形式(月別シートで、A列に「日付」「予定1」…のラベル、日付が横に並び、セルに予約確定メールの本文が入る形式): 月別シートをまとめて読み込み、メール本文からお客様名・日時・プランを、「売上」行から金額を読み取ります。確定メール以外のセル(問い合わせフォームの写し、予約サイト経由、スタッフ利用など)も「売上」に金額があれば予約として取り込みます。キャンセルの記載があるもの、金額のないメモ、別スタジオの予約メールは対象外です。月の「売上額」行は一部の予約を数えていないことがあるため、金額は各予約の「売上」を使います
- 読み込みは閲覧のみの権限(`spreadsheets.readonly` / `calendar.readonly` / `drive.readonly`)で、接続したユーザーのGoogleアカウントの権限で行います。アクセストークンはブラウザのメモリ上にだけ保持します

初期設定(Google Cloud Console、プロジェクト `studiomanager-5eb1d`):

1. 「Google Sheets API」「Google Calendar API」「Google Drive API」を有効にする
2. OAuth同意画面を設定する
3. 「認証情報」→「OAuthクライアントID」(ウェブアプリケーション)を作成し、承認済みのJavaScript生成元に `https://studio.metalandtokyo.xyz` などを追加する
4. 発行されたクライアントIDを `index.html` の `GOOGLE_OAUTH_CLIENT_ID` に設定する

## アカウント

- 新規登録画面はなく、アドミンが「メンバー管理」から招待します。招待された人にはパスワード設定メールが届きます。
- 初期セットアップ時のみ、最初にログインしたユーザーが自動的にアドミンになります(Firestore の `system/bootstrap` が作成された時点でこの経路は閉じます。設定済み)。

firebase deploy
